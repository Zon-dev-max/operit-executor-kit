# 工作区管理·索引与归档规范

版本：v1.1

> 读我的人＝执行项目的 AI。开工前读完，全程照做。
> **定位：横切规范，始终生效**——不依附任何单一任务，凡涉及多项目、长任务文件管理、索引维护、归档操作都适用。
> 与《任务五步走·落盘规范》配合使用：单项目内部结构仍严格遵守后者，本规范负责项目之间的组织与生命周期。

## 0. 何时用（触发）

- 工作区项目数量 ≥ 5 个，或单项目 step 超过 20 个
- 需要快速知道「哪些在进行、哪些已完成、哪些可归档」
- 用户要求建立/更新索引、执行归档、清理膨胀文件
- 扫描工作区后发现目录混乱、空项目、断层、垃圾堆积
- 长任务跨多天/多周，需要保持可回溯性

## 0.1 核心原则（写死）

1. **一个项目一个独立工作区**，绝不在同一目录下混合多个不相关任务。
2. **状态用目录体现，不写进项目名**（项目名保持干净、等于任务名）。
3. **索引是轻量总览，不是第二套日志**。索引只记录状态、路径、一句话摘要，不复制交接单内容。
4. **归档是移动整目录，不是复制或删除内部文件**。
5. **成功交付物永不主动删除**；临时物必须清零。
6. **先建索引再动手归档**，避免找不到东西。

## 1. 标准目录分层（唯一允许的布局）

```text
/sdcard/Download/Operit/workspace/
├── active/                 # 正在进行的项目（唯一允许新建的地方）
│   ├── <项目名A>/
│   ├── <项目名B>/
│   └── ...
├── done/                   # 已完成、验收通过、但仍可能回头查看的项目
│   ├── 2026-10/
│   │   ├── <项目名C>/
│   │   └── <项目名D>/
│   └── 2026-09/
│       └── ...
├── archive/                # 彻底封存、确认长期不需要的项目
│   ├── 2026-Q3/
│   └── ...
└── INDEX.md                # 全局轻量索引（必须存在）
```

固定规则：

- 新项目**必须**建在 `active/` 下。
- 项目内部结构严格遵守《任务五步走·落盘规范》：`{plan,src,tmp,logs}`，不得新增第五个子目录。
- `done/` 和 `archive/` 下按「年月」或「季度」再分子目录，便于时间维度管理。
- 禁止在 `workspace/` 根目录直接放项目文件夹。
- 禁止在 `active/`、`done/`、`archive/` 下再创建其他自定义层级。

## 2. 全局索引（INDEX.md）规范

位置：`/sdcard/Download/Operit/workspace/INDEX.md`（固定，不可移动）

### 2.1 必须包含的字段

```markdown
# 工作区全局索引

最后更新：YYYY-MM-DD HH:MM

## 进行中（active）
| 项目名 | 当前 step | 一句话状态 | 路径 | 最后活动 |
|--------|-----------|------------|------|----------|
| 项目A  | step_12   | 等待用户确认方案 | active/项目A/ | 2026-10-13 |

## 已完成（done）
| 项目名 | 完成日期 | 最终产物摘要 | 路径 |
|--------|----------|--------------|------|
| 项目C  | 2026-10-10 | 角色卡 v3.6 已交付 | done/2026-10/项目C/ |

## 归档（archive）
| 项目名 | 归档日期 | 备注 | 路径 |
|--------|----------|------|------|
| 旧项目X | 2026-09-01 | 长期不用 | archive/2026-Q3/旧项目X/ |

## 巡检记录（最近一次）
- 时间：
- 发现的问题：
- 已处理：
```

### 2.2 更新规则

- 每次新建项目、完成项目、执行归档、发现异常后，必须更新 INDEX.md。
- 更新时只改对应表格行，不重写整个文件。
- 「一句话状态」限制在 20 字以内，只描述当前阻塞点或下一步。
- 禁止把 plan/logs 的详细内容复制进 INDEX.md。
- 「最后活动」字段：每次 update plan/logs 时顺手刷新对应行，不要等归档时才刷。

## 3. 生命周期操作（完整流程）

### 3.1 新建项目

1. 确认项目名干净（无日期、无状态词、无空格）。
2. 在 active/ 下创建完整结构：

```bash
active/<项目名>/{plan,src,tmp,logs}
```

3. 立即更新 INDEX.md 的「进行中」表格。
4. 写 plan/step_1.md（按《任务五步走·落盘规范》）。

### 3.2 项目完成（验收通过）

1. 确认所有 step 的 plan 与 logs 1:1 配对、tmp 已清零、正式产物在 src/ 或交付位。
2. 整目录移动：

```bash
mv active/<项目名> done/YYYY-MM/
```

3. 更新 INDEX.md：从「进行中」删除，加入「已完成」。
4. 如有交付物，确认已复制到 /sdcard/Download/<项目名>-交付/。
5. 如该项目是子任务（见 §3.5），需同步在其父项目的最新交接单里标注「已交付」并附新路径。

### 3.3 归档（彻底封存）

触发条件（满足任一即可）：

- 进入 done 超过 30 天且用户确认不再需要
- 用户明确说「归档」
- 巡检发现长期无活动且无未关闭问题

操作：

1. 整目录移动到 archive/YYYY-QN/ 或 archive/YYYY-MM/。
2. 更新 INDEX.md。
3. 不删除任何内部文件。

### 3.4 单项目内部文件膨胀处理

当单个项目的 plan/ 或 logs/ 超过 25 个文件时：

- 在项目根创建 INDEX.md（项目级轻量索引），只列 step 编号 + 一句话。
- 早期已稳定的 step 可合并过程记录到 src/历史过程/，但最终交接单必须保留在 logs/。
- 禁止删除任何 logs/step_*.md。

### 3.5 子任务截断（长任务拆解）

**触发条件**（满足任一）：
- 单项目预估 step > 20
- 单项目剩余步骤 ≥ 10 且剩余部分是独立可交付单元
- 单项目单次对话上下文装不下剩余步骤

**拆法**：
1. 主项目在截断点 step_N 的交接单「下一步」栏写：`后续见子项目 <子项目名>，上游依赖 step_N`。
2. 在 active/ 下建子项目：`active/<主项目名>-<阶段名>/`。阶段名用短语义词（如 `-阶段2`、`-收尾`），不带日期。
3. 子项目 step_1 的上游依赖写：`主项目 <主项目名> / logs/step_N.md`。
4. 子项目在 INDEX.md「进行中」表格新增一行，「一句话状态」注明 `承接 <主项目名> step_N`。
5. 主项目保留原 step_1..step_N，不搬走、不归档，等待子项目完成后一并处理。

**禁止**：
- 用对话记忆当截断依据（必须落盘到主项目 logs）
- 子项目另起一个不相关名字（必须能看出承接关系）
- 主项目与子项目同时改同一个文件（截断点后主项目即冻结）

## 4. 巡检与自愈（定期执行）

每次用户要求「检查工作区」或「整理文件」时，必须按以下顺序执行：

1. 扫描目录结构
   - 检查是否有项目出现在错误位置（根目录、done 下混有 active 等）
   - 检查是否有空项目、无 plan/logs 的目录
2. 断层检查（沿用《任务五步走·落盘规范》的命令）

```bash
for d in /sdcard/Download/Operit/workspace/active/*/; do
  diff <(ls "$d/plan" 2>/dev/null | sort) <(ls "$d/logs" 2>/dev/null | sort) >/dev/null \
    || echo "断层: $d"
done
```

3. 更新 INDEX.md
   - 重新统计 active / done / archive 数量
   - 刷新「最后活动」时间
   - 记录本次巡检结果
4. 报告
   - 只报告真实发现的问题与已执行的动作
   - 给出可复现证据（命令 + 输出）
   - 不主动删除任何项目，除非用户明确授权

## 5. 禁止项（违反＝失败）

- 在 workspace 根目录或 active/done/archive 下自创额外层级
- 项目名带日期、状态词、版本号
- 把详细交接单内容复制进 INDEX.md
- 只复制项目而不移动（导致双份）
- 删除 done 或 archive 中的任何文件
- 在 tmp/ 以外的地方堆积临时文件
- 不更新 INDEX.md 就进行归档或新建
- 用对话记忆代替 INDEX.md 作为项目状态来源

## 6. 收尾与验证

每次执行本规范相关操作后：

1. 重开 INDEX.md，确认内容与实际目录一致
2. 运行一次断层检查（仅 active）
3. 汇报固定格式：

```text
当前：工作区管理 / 已更新索引与归档状态 / 等待下一步指令
```

4. 所有证据（命令输出、文件列表）落盘到当前操作相关的 logs 或直接在对话给出路径

## 7. 与其他规范的关系

- 单项目内部的 plan/logs/src/tmp 规则 → 完全服从《任务五步走·落盘规范》
- 本规范只负责项目之间的组织、索引、生命周期
- 冲突时以更严者为准

```bash
mv /sdcard/Download/Operit/workspace/active/<项目名> /sdcard/Download/Operit/workspace/done/$(date +%Y-%m)/

mkdir -p /sdcard/Download/Operit/workspace/archive/$(date +%Y)-Q$(( ($(date +%-m)-1)/3+1 ))
mv /sdcard/Download/Operit/workspace/done/YYYY-MM/<项目名> /sdcard/Download/Operit/workspace/archive/...

# 断层检查（active）
for d in /sdcard/Download/Operit/workspace/active/*/; do
  diff <(ls "$d/plan" 2>/dev/null | sort) <(ls "$d/logs" 2>/dev/null | sort) >/dev/null || echo "断层: $d"
done
```
